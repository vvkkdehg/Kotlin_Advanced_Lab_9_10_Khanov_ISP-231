## Геттеры и сеттеры
___
___Геттеры и сеттеры___ — термины, которые в программировании обозначают механизмы доступа к данным внутри объекта через посредника. 
Название происходит от английского слов get («получать») и set («устанавливать»).
```kotlin
var energy: Int = maxEnergy
        set(value) {
            field = value.coerceIn(0, maxEnergy)
        }
    var mood: Int = 50
        get() = field + (energy / 10)
```
## Инкапсуляция
___
___Инкапсуляция___ — принцип объектно-ориентированного программирования, 
который позволяет скрыть внутреннюю реализацию класса и предоставить контролируемый доступ к его данным.
Увеличение параметра Level только с помощью метода:
```
var level: Int = 1
    private set
    fun levelUp(){
        level++
        println("$name повысил уровень до $level")
    }
```
## Data-классы
___
___Data class___ в языке программирования Kotlin — специальный тип класса, 
предназначенный для представления небольших, простых объектов данных.
```
data class OutpostResource(
    val id: Int,
    val name: String,
    var amount: Int
) {
    override fun toString(): String {
        return "Ваш ресурс: $id | Имя: $name | Количество: | $amount"
    }
}
```
## Абстрактные классы
___
___Абстрактный класс___ в Kotlin — это класс, от которого нельзя создавать объекты. 
Он используется лишь в качестве суперкласса, 
в который вынесено всё общее из дочерних классов.
```
abstract class OutpostModule (
    val name: String,
    var level: Int = 1
) {
    fun upgrade() {
        level++
        println("$name улучшен до уровня $level")
    }
    abstract fun performAction(manager: ResourseManager)
}
```
## Интерфейсы
___
Это __контракт поведения__

Содержит:

* функции без реализации;
* функции с default-реализацией;
* свойства без хранения (только декларации)

#### Пример

#### Определяем интерфейс видео-плеера:
```
interface VideoPlayable {
    fun play() = println("Play video")
}
```

#### Определяем интерфейс аудио-плеера
```
interface AudioPlayable {
    fun play() = println("Play audio")
}
```

Далее создадим класс, который будет реализовывать оба интерфейса, 
и в нем переопределим метод для обоих интерфейсов 
```
class MediaPlayer : VideoPlayable, AudioPlayable {
    override fun play() {
        println("Start playing")
        super<VideoPlayable>.play()
        super<AudioPlayable>.play()
    }
}
```
